# Sharing: link previews, feed, sitemap — contract

How What Works? travels: the preview card a link gets when it's pasted into Discord, Bluesky, X, Facebook,
iMessage, Slack or a YouTube description, plus a feed people can subscribe to and a sitemap for search engines.

## Settings (`site.toml`)

- `site_url = "https://castor-o7.github.io"` — the origin. Absolute URLs are `site_url + base_url + path`.

## Link previews (every page, in `base.html`)

`<link rel="canonical">`, `og:site_name`, `og:title`, `og:description`, `og:url`, `og:type` (`article` for posts,
`website` otherwise), `og:image` (+ `og:image:width`, `og:image:height`, `og:image:alt`), `twitter:card`
(`summary_large_image`), and for posts `article:published_time`. All URLs absolute. Descriptions: the post or tool
`summary`, a section's blurb, or the site tagline; plain text, HTML-escaped, ≤ 200 characters.

**Share image** for a post, first match wins:
1. `image:` front matter — a file in `content/images/` (e.g. `image: grid-map.png`) or a full `https://` URL.
2. The post's YouTube `video:` → `https://i.ytimg.com/vi/<id>/hqdefault.jpg` (always exists; 480×360).
3. A generated **title card**: `_site/static/og/<slug>.png`, 1200×630, in the site's style — paper background
   (`#f7f5f0`), the headline in Fraunces (bold, wrapped, shrunk to fit), the section kicker in the accent color
   (`#c2410c`), "What Works?" with the orange "?" at the bottom. Tools get one too (`og/tool-<slug>.png`).
4. The default site card `_site/static/og/site.png` (wordmark + tagline), used by every other page.

Cards are generated by `scripts/build_site.py` with Pillow from fonts vendored in `app/fonts/` (Fraunces and
Source Sans 3, SIL Open Font License, with their `OFL.txt`). Output must be deterministic (same input → same bytes),
so redeploys don't churn git. Unchanged cards should not be regenerated needlessly if it's slow.

## Feed (`/feed.xml`, Atom 1.0)

- The 20 newest **published** posts (never drafts, even in a `--drafts` preview build).
- Each entry: title, permalink (as `id` and `link`), `published`/`updated` from the post date, summary, author,
  category (section label), and the full HTML `content` with every link and image made absolute.
  `<figure class="storm-chart">` and `<figure class="then-now">` (drawn by JavaScript, so empty in a feed reader)
  become a paragraph link: "Interactive chart: <title or a description> — view it on What Works? →".
  A post's video becomes a link at the top of its content.
- `<link rel="alternate" type="application/atom+xml" title="What Works?" href="…/feed.xml">` in every page's head;
  a visible "Subscribe (RSS)" link in the footer and on the About page.

## Sitemap + robots

`/sitemap.xml` lists every published page (home, sections, posts, Storm Desk, Then & Now, tools, about; not the
event-page shell, not 404). `/robots.txt` at the site root can't be served from a project site (`/whatworks/robots.txt`
is ignored by crawlers), so don't rely on it; the sitemap is referenced from the page head instead
(`<link rel="sitemap" type="application/xml" href=…>`).

## Publishing

`content/images/` files are copied to `_site/images/`. `scripts/publish.py` backs up an image to GitHub **only if a
published post or tool references it** (an image only a draft uses stays private, like the draft). The pre-commit hook
needs no change (it checks `.md` drafts). `docs/WRITING.md` gets a "Sharing" section: the `image:` key, what the
preview will look like, the feed URL, and how to check a preview (paste the link in a Discord DM to yourself, or use
a preview tool).
